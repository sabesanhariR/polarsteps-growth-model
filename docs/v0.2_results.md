# v0.2 Results (vs v0.1)

Same seed (42), same calibrated draws (43,756 kept of 50,000). Code: branch `dev`, commit `2f8c7fa`.

## Regression check
Cumulative-user outputs are identical to v0.1 (P(reach 100M within 5y) = 56.7%; within 10y = 99.2%).

## What changed
v0.2 adds an active-user output: active users = cumulative users × `active_share` (a static ratio, no churn; a rescaling, not a retention model). Active target: 25M (placeholder, about 100M × the prior mode of `active_share`).

## Reading it
- 100M registered users at year 5 corresponds to roughly 28M active users (range 19M to 40M), a less dramatic headline than v0.1.
- Active-target time is shorter early because the median `active_share` (0.27) is above the 0.25 behind the placeholder target. It plateaus near 94% because in some draws `addressable_m × active_share` (about 6%) is below the target, so it can never be reached.
- The 25M target is a judgement. The year-5 and year-10 levels are the more defensible output.

## Sensitivity (Spearman, active target)
`active_share` -0.91, `addressable_m` -0.79, `conversion` +0.54, `invites_per_trip` -0.06, `paid_share_start` +0.09, `paid_decay` +0.03.
`active_share` ranks first partly by definition: it sets how many cumulative users the target needs. It should not be read as a growth lever. Signs are also affected by calibration, which holds `k` fixed.

## Limits
- Static ratio, no churn or cohort retention.
- `addressable_m` depends on a placeholder world multiplier, and the ceiling drives the long-run results.
- Implied `conversion` (median 0.29) is far above its prior range, so it absorbs growth beyond the modelled invite loop.
- Outside-in model on public data; not a forecast.
